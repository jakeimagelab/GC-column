# 콘텐츠 편집 슬라이드 — 정밀 배치·모션 보완

## 구현 결과

| 항목 | 결과 | 내용 |
| --- | --- | --- |
| 실제 화면 직접 글자 편집 | 통과 | `내용 편집`에서 등록된 글자 요소를 한 번 클릭하면 즉시 커서가 생기며, 포커스를 벗어나면 자동 저장한다. |
| 오른쪽 관련 도구 | 통과 | 글자는 내용·폰트·크기·굵기·행간·자간·색·투명도·정렬, 이미지는 크롭·초점·확대·투명도·컬러·그라데이션·alt 도구가 표시된다. |
| 모든 항목 공통 배치 | 통과 | 글자·사진·배경 모두 PC/모바일별 X·Y·배율·회전·레이어 값을 가진다. `위치 이동`에서 드래그, 휠 크기 조절, 방향키 1px, Shift+방향키 10px 이동이 가능하다. |
| 이미지 직접 배치 | 통과 | 실제 디자인의 점선 이미지 자리에 Finder 파일을 드롭할 수 있고, 기존 교체 확인·크롭·초점·확대 저장 흐름을 유지한다. |
| 나타나는 모션 | 통과 | 없음·4방향 페이드·확대/축소·블러·커튼·자간 모션과 시간·지연·거리·이징을 항목별로 저장한다. 선택 항목 또는 현재 슬라이드 전체 미리보기를 제공한다. |
| 반응형 편집 | 통과 | PC 값과 모바일 값을 분리 저장하며 모바일 값이 없을 때 PC 배치를 이어받는다. |
| 기존 데이터 호환 | 통과 | 이전 `content-board.json`을 읽을 때 배치·모션·글자 투명도의 기본값을 자동 보완한다. |
| 개발 전용 보호 | 통과 | `/content-board`와 `/api/dev-content-board`는 기존대로 개발 모드에서만 열리고 운영 빌드에서는 404를 유지한다. |

## 확인 기록

- 실제 디자인에서 글자를 선택했을 때 오른쪽 `TEXT` 검사기와 공통 배치·모션 도구가 표시되는 것을 확인했다.
- `**원장 칼럼**`처럼 굵게 저장된 한 덩어리 글자를 클릭해도 별표가 중복되지 않도록 보정했다.
- 모션 프리셋 저장과 선택 항목 미리보기를 확인했다.
- 오른쪽 미세 이동 버튼으로 X 좌표가 저장되는 것을 확인했고, 이동 모드에서 선택 요소에 키보드 포커스가 유지되도록 보완했다.
- 테스트 중 변경된 콘텐츠 보드 파일은 검증 전 원본으로 복원했다.
- `npm run build`: 성공.

## 저장되는 개발 지시 정보

배치와 모션은 `content-brief/content-board.json`에 항목 ID별로 저장된다. 이 파일은 실제 사이트 레이아웃을 즉시 덮어쓰는 운영 CMS가 아니라, 실제 디자인 위에서 확정한 콘텐츠·배치·연출 지시를 다음 코드 반영 때 그대로 읽기 위한 로컬 콘텐츠 보드다.
